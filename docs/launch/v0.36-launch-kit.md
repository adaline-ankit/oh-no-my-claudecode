## Positioning

**Category:** memory-grounded execution layer for coding agents

**One line:** ONMC runs Claude Code or Codex in bounded autonomous loops that remember repo history,
avoid known failed approaches, verify completion with real commands, and leave a tamper-evident receipt.

**Tagline:** Your agent remembers the failure. Your tests decide when it is done.

**Do not lead with:** generic memory, token savings, dashboards, or "another orchestrator."

**Lead with:** a real coding agent attempts a task, learns from failure, passes the verifier, and produces
evidence that can be replayed.

## 90-second demo

Use a small public repo with one failing test and one seeded failed-approach memory.

```bash
pip install oh-no-my-claudecode
cd demo-repo
onmc setup --no-llm

onmc guard --task "fix coupon calculation"

onmc loop \
  --goal "fix coupon calculation without changing public API" \
  --agent claude \
  --verify "pytest -q" \
  --max-iterations 4 \
  --max-cost-usd 1.00 \
  --max-wall-seconds 300
```

Show, in order:

1. `guard` surfaces the bad approach before execution.
2. Loop runs real agent and real tests.
3. Failed iteration becomes future memory.
4. Final result says `VERIFIED` only after tests pass.
5. Open `.agent-memory/receipts/` and show goal, verifier, diff hash, limits, and hash chain.
6. Run `onmc replay run <trace-id> --compare` to show where memory changed the session.

Keep terminal readable. Do not spend demo time on every command.

### Body

```markdown
Coding agents are good at writing code, but the workflow around them still has two weak points:
they retry approaches that failed in earlier sessions, and "done" often means the model stopped
rather than the repository passed a real verifier.

I built ONMC (oh-no-my-claudecode), an MIT-licensed local execution and memory layer for Claude Code
and Codex.

Its autonomous loop does this:

1. compile task-specific context from git, docs, code, PRs, and prior sessions
2. inject matching failed approaches before every iteration
3. run the real `claude -p` or `codex exec` CLI
4. execute a verifier you choose
5. stop on convergence, no progress, iterations, tokens, cost, or wall time
6. write a tamper-evident receipt containing verifier result and repository/diff hashes

A run is marked verified only when the loop converges and the final verifier exits successfully.
The receipt is SHA-256 hash-chained, not signed.

Quickstart:

```bash
pip install oh-no-my-claudecode
cd your-repo
onmc setup
onmc loop --goal "fix the failing checkout tests" --agent claude --verify "pytest -q" --dry-run
```

ONMC also ships deterministic memory evals, trace replay, agent-config security audit, MCP call policy,
GitHub Agentic Workflow scaffolding, a local dashboard, Claude Code hooks, and 12 MCP memory tools.

Memory exports as human-readable `.agent-memory/` JSON, so it can travel with git to Codex, Cursor,
cloud agents, or another machine. Core recall/eval/replay/audit paths work without an LLM or hosted account.

Proof caveat: the headline repeated-failure and context-token numbers from `onmc bench` are a labelled
deterministic simulation, not production LLM measurements. `onmc benchmark` separately reports measured
latency and compression against your own repo brain.

GitHub: https://github.com/adaline-ankit/oh-no-my-claudecode
PyPI: https://pypi.org/project/oh-no-my-claudecode/
```
